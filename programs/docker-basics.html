Docker من الفكرة إلى النشر: صورة واحدة تنقل مشروعك أينما ذهبت

Dockerfile نظيف، طبقات مخزّنة، docker compose لبيئة تطوير كاملة، وأخطاء شائعة ترفع حجم الصورة 10 أضعاف.

ععاصم محمد
· 2025-01-03 · 13 دقيقة قراءة · متوسط
🐳

«يعمل على جهازي فقط» ليست مشكلة تواصل — هي مشكلة بيئة. Docker يحوّل بيئتك إلى ملف نصي يمكن نسخه. لكن الفرق بين Dockerfile يعمل و Dockerfile جيد كبير.

لماذا Docker؟

  • تطابق: نفس الإصدارات على جهازك والمخدّم و CI.
  • عزل: مشروعان بإصدارين مختلفين من نفس اللغة بلا تعارض.
  • سرعة الاستعادة: بيئة جديدة كاملة في ثوانٍ.

Dockerfile نظيف (Node)

# --- المرحلة 1: البناء ---
FROM node:20-alpine AS build
WORKDIR /app

# انسخ ملفات الاعتماديات أولاً — لاستغلال التخزين المؤقت
COPY package*.json ./
RUN npm ci

COPY . .
RUN npm run build

# --- المرحلة 2: التشغيل ---
FROM node:20-alpine AS runtime
WORKDIR /app
ENV NODE_ENV=production

# مستخدم غير جذري (أمان)
RUN addgroup -S app && adduser -S app -G app

COPY --from=build /app/dist ./dist
COPY --from=build /app/node_modules ./node_modules
COPY package.json ./

USER app
EXPOSE 3000
CMD ["node", "dist/server.js"]

النتيجة: صورة نهائية صغيرة، بلا أدوات بناء، وبلا صلاحيات جذر.

الطبقات والتخزين المؤقت

كل سطر في Dockerfile طبقة. Docker يعيد استخدام الطبقة فقط إن لم يتغيّر ما قبلها. لذلك ترتيب الأسطر هو قرار أداء:

# ❌ أي تعديل في الكود يعيد تثبيت الاعتماديات كاملة (~3 دقائق)
COPY . .
RUN npm ci

# ✅ تغيير الكود لا يمسّ طبقة الاعتماديات
COPY package*.json ./
RUN npm ci
COPY . .

بيئة كاملة بأمر واحد

services:
  app:
    build: .
    ports: ["3000:3000"]
    environment:
      DATABASE_URL: postgres://app:secret@db:5432/appdb
      REDIS_URL: redis://cache:6379
    depends_on:
      db:
        condition: service_healthy
    volumes:
      - ./src:/app/src        # تطوير مباشر مع إعادة تحميل

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: secret
      POSTGRES_DB: appdb
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app -d appdb"]
      interval: 5s
      retries: 5

  cache:
    image: redis:7-alpine

volumes:
  pgdata:
docker compose up -d        # شغّل الكل
docker compose logs -f app  # تابع السجلات
docker compose down -v      # أوقف واحذف البيانات (احذر)

لاحظ healthcheck: بدونه قد يبدأ التطبيق قبل أن تكون قاعدة البيانات جاهزة، فتفشل أول محاولة اتصال.

أخطاء شائعة

  1. نسخ .env داخل الصورة: أسرارك تصبح في الطبقات. استخدم --env-file أو مدير أسرار.
  2. COPY . . قبل npm ci: كل تغيير يعيد التثبيت.
  3. عدم استخدام healthcheck: أخطاء اتصال عشوائية عند البداية.
  4. كتابة بيانات داخل الحاوية: تُفقد عند الحذف. استخدم volumes.
  5. عملية الجذر (root): مخاطرة أمنية حقيقية. أضف USER.
الخطوة التالية: أضف .dockerignore إلى مشروعك الحالي وأعد البناء. قارن الحجم بـ docker images قبل وبعد — التوفير غالباً أكبر مما تتوقع.
