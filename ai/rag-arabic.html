بناء نظام RAG عربي دقيق: من التقطيع إلى قياس الجودة

معظم أنظمة RAG تفشل لا لأن النموذج ضعيف، بل لأن التقطيع والاسترجاع سيئان. دليل هندسي كامل: تقطيع عربي واعٍ، بحث هجين، إعادة ترتيب، وقياس بالمقاييس الحقيقية.

RAG

أغلب من يبني نظام RAG لأول مرة يظن أن المشكلة في النموذج. ثم يجرب نموذجاً أكبر، فتتحسن النتيجة قليلاً — ثم تعود الأخطاء. السبب الحقيقي في الغالب: المقاطع التي تُرسل للنموذج لا تحتوي الجواب أصلاً. لا نموذج في العالم يستطيع الإجابة من نصٍّ غائب.

لماذا تفشل أنظمة RAG؟

عند تحليل مئات الحالات الفاشلة، تتكرر خمسة أسباب بهذا الترتيب:

السببنسبة الحالاتالعلاج
تقطيع يقطع الجملة عن سياقها~40%تقطيع حسب البنية + تداخل
استرجاع يفوّت المقاطع الصحيحة~25%بحث هجين (كلمات + متجهات)
مقاطع طويلة تُضعف التركيز~15%إعادة ترتيب + ضغط السياق
غياب المصادر في الجواب~10%إلزام النموذج بالاقتباس
نموذج فعلاً ضعيف في العربية~10%استبدال النموذج
القاعدة: حسّن الاسترجاع قبل أن تلمس النموذج. كل نقطة تحسين في Recall تساوي عشر نقاط في جودة الجواب النهائي.

التقطيع العربي: ما لا يخبرك به أحد

التقطيع الأعمى كل 500 حرف يقطع الجمل العربية في منتصفها، ويفصل الضمير عن مرجعه، ويخلط بين فقرة المقدمة وفقرة الاستنتاج. النتيجة: مقطع يقول «وهو ما يجعلها أسرع بثلاثة أضعاف» بدون أن نعرف ما هي «هي».

  • قسّم على البنية لا على العدد: رؤوس العناوين h2/h3، الفقرات، صفوف الجداول.
  • حافظ على المسار الهرمي: أضف لكل مقطع عنوان القسم الأعلى كتمهيد — هذا يضاعف دقة البحث.
  • تداخل 15–20%: الجملة التي تبدأ مقطعاً تحتاج نهايته.
  • لا تخلط اللغتين: النص التقني العربي مليء بمصطلحات إنجليزية؛ أبقِها كما هي ولا تترجم.
{{
chunker.py
def chunk_document(md: str, max_chars=900, overlap=150):
    # تقطيع واعٍ بالبنية: يحتفظ بالعنوان الأب كتمهيد لكل مقطع.
    chunks, parent, buf = [], "", ""
    for block in md.split("\\n\\n"):
        line = block.strip()
        if line.startswith("#"):
            parent = line.lstrip("# ").strip()
            continue
        if len(buf) + len(line) > max_chars and buf:
            chunks.append({{"text": f"[{{parent}}]\\n{{buf}}", "parent": parent}})
            buf = buf[-overlap:]          # تداخل يمنع قطع السياق
        buf += "\\n" + line
    if buf.strip():
        chunks.append({{"text": f"[{{parent}}]\\n{{buf}}", "parent": parent}})
    return chunks
}}

التضمين والفهرسة

النماذج متعددة اللغات تعمل بالعربية، لكن أداءها يتفاوت كثيراً. اختبر قبل أن تلتزم:

النموذجعربيالأبعادملاحظة
multilingual-e5-largeجيد جداً1024أفضل توازن جودة/حجم
bge-m3ممتاز1024يدعم نصوصاً طويلة
arabert / arabert-v2ممتاز (نص)768متخصص، يحتاج تخصيصاً للمهمة
{{
embed.py
import numpy as np

def embed_chunks(chunks, model, batch=32):
    # تضمين دفعات مقصوصة — الذاكرة تبقى ثابتة مهما كبر المستند.
    out = []
    for i in range(0, len(chunks), batch):
        batch_txt = [c["text"] for c in chunks[i:i + batch]]
        vecs = model.encode(batch_txt, normalize_embeddings=True)
        out.extend(vecs.astype(np.float32))
    return np.vstack(out)
}}
قاعدة عملية: طبّع المتجهات (normalize) عند الحفظ واستخدم cosine حتى لو كانت المكتبة تتحدث عن الضرب النقطي — الاثنان يتطابقان بعد التطبيع.

البحث الهجين: سرّ الفرق بين نظام «مقبول» و«ممتاز»

البحث المتجهي ممتاز في المعنى، لكنه يخفق في الأسماء الدقيقة: أسماء الدوال، أرقام الإصدارات، المصطلحات التقنية النادرة. البحث الكلمي (BM25) يفعل العكس تماماً. الدمج بينهما يحل المشكلتين.

{{
hybrid.py
def hybrid_search(query, k=10, alpha=0.6):
    # alpha يحدد وزن البحث المتجهي مقابل الكلمي.
    dense = vector_index.search(embed(query), k=k * 3)
    sparse = bm25_index.search(tokenize(query), k=k * 3)

    scores = {{}}
    for rank, (doc_id, _) in enumerate(dense):
        scores[doc_id] = scores.get(doc_id, 0) + alpha / (rank + 60)
    for rank, (doc_id, _) in enumerate(sparse):
        scores[doc_id] = scores.get(doc_id, 0) + (1 - alpha) / (rank + 60)

    return sorted(scores, key=scores.get, reverse=True)[:k]
}}

ثابت 60 مأخوذ من خوارزمية Reciprocal Rank Fusion: يعمل جيداً دون ضبط، ويوزّع الوزن على الترتيب لا على القيمة المطلقة — وهذا مهم لأن درجات المتجهات ومعايير BM25 غير قابلة للمقارنة أصلاً.

إعادة الترتيب (Reranking)

الاسترجاع الأول يبحث في ملايين المقاطع بسرعة. إعادة الترتيب تأخذ أفضل 30 نتيجة وتعيد تقييمها بنموذج أدق وأبطأ. التكلفة صغيرة، والفرق كبير.

{{
rerank.py
from sentence_transformers import CrossEncoder

reranker = CrossEncoder("BAAI/bge-reranker-v2-m3")

def rerank(query, candidates, top_n=5):
    pairs = [(query, c["text"]) for c in candidates]
    scores = reranker.predict(pairs)
    ranked = sorted(zip(candidates, scores), key=lambda x: -x[1])
    return [c for c, _ in ranked[:top_n]]
}}

قياس الجودة: لا تُحسّن ما لا تقيسه

أنشئ 50 سؤالاً حقيقياً من مستخدميك مع الجواب الصحيح في مستند معروف. ثم قِس:

المقياسالسؤالالهدف
Recall@kهل المقطع الصحيح ضمن أفضل k؟> 0.9
MRRفي أي مرتبة ظهر أول مقطع صحيح؟> 0.75
Faithfulnessهل كل جملة في الجواب مدعومة بالمصدر؟> 0.95
Answer Relevanceهل يجيب فعلاً عن السؤال المطروح؟> 0.85
{{
eval.py
def recall_at_k(retrieved, gold_ids, k=5):
    # نسبة الأسئلة التي ظهر جوابها الصحيح في أعلى k نتائج.
    return sum(any(d in gold_ids for d in retrieved[:k]) for _ in [0]) / len(gold_ids)

# ملاحظة: طبّق على مجموعة أسئلة كاملة، لا على سؤال واحد.
}}

قائمة الإنتاج

  1. ألزم النموذج بالاقتباس: كل جملة تنتهي بمرجع [3].
  2. علّم النموذج أن يقول «لا أعرف» — الجواب الصادق أفضل من تخمين مقنع.
  3. حدّد مهلة زمنية للاسترجاع: مستخدم لا ينتظر 8 ثوانٍ.
  4. خزّن الأسئلة بلا جواب — هي خارطة طريقك لأهم مستندات ناقصة.
  5. أعد الفهرسة عند كل تحديث للمستندات، واحفظ نسخة من كل إصدار.
الخطوة التالية: خذ 10 أسئلة فعلية من مستخدميك، وشغّل عليها نظامك الحالي، واحسب Recall@5 يدوياً. هذا الرقم وحده سيخبرك أين تكمن المشكلة.
