بناء وكيل ذكاء اصطناعي (AI Agent) يفهم أدواتك ويستخدمها

من Function Calling إلى RAG إلى التخطيط الذاتي: خريطة طريق لبناء وكيل عملي يربط بين النماذج اللغوية وبيانات شركتك.

ععاصم محمد
· 2025-02-06 · 18 دقيقة قراءة · متقدم
AI

معظم من يبدأ في الذكاء الاصطناعي يتوقف عند «اسأل النموذج وخُذ الجواب». لكن القيمة الحقيقية تظهر عندما يتحوّل النموذج من مُجيب إلى مُنفّذ: يقرأ بياناتك، يستدعي أدواتك، ويصل إلى نتيجة دون أن تكتب سطراً لكل حالة.

ما هو الوكيل؟

النمطما يفعلهمثال
Promptسؤال ← جواب«لخّص هذا المقال»
RAGسؤال ← استرجاع ← جواب من مستنداتك«ما سياسة الاسترجاع في دليلنا؟»
Agentهدف ← خطة ← أدوات ← مراجعة ← نتيجة«ابحث عن الأخطاء في السجلات وأصلحها»

الوكيل = نموذج + أدوات + حلقة. لا شيء أكثر من ذلك. التعقيد كله في جودة الأدوات ووضوح الحدود.

Function Calling

الأداة هي دالة عادية تصفها للنموذج بشكل صريح. النموذج لا يُنفّذها؛ هو فقط يقرر أيها يُستدعى وبأي وسائط، ثم أنت تُنفّذ وتُرجع النتيجة.

TOOLS = [{
    "name": "search_orders",
    "description": "ابحث عن طلبات عميل برقمه أو بريده. استخدمها دائماً قبل الإجابة عن حالة طلب.",
    "parameters": {
        "type": "object",
        "properties": {
            "customer_email": {"type": "string", "description": "بريد العميل"},
            "status": {
                "type": "string",
                "enum": ["pending", "shipped", "delivered"],
                "description": "فلترة اختيارية بحالة الطلب"
            }
        },
        "required": ["customer_email"]
    }
}]

def search_orders(customer_email: str, status: str | None = None) -> list[dict]:
    q = db.orders.where(customer_email=customer_email)
    if status:
        q = q.where(status=status)
    return [{"id": o.id, "status": o.status, "total": o.total} for o in q]
قاعدة ذهبية: وصف الأداة أهم من كودها. النموذج يقرأ الوصف ليقرر. اكتب الوصف كما تشرح لمهندس جديد متى يستخدم هذه الأداة ومتى لا.

RAG: المعرفة

النموذج لا يعرف سياسة شركتك ولا مستنداتك. RAG يحل ذلك بثلاث خطوات:

  1. تقطيع (Chunking): قسّم المستندات إلى أجزاء 300–800 رمز مع تداخل بسيط.
  2. تضمين (Embedding): حوّل كل جزء إلى متجه رقمي وخزّنه في قاعدة متجهات.
  3. استرجاع: عند السؤال، ابحث عن أقرب 3–5 أجزاء وأضفها إلى السياق.
def build_context(question: str, k: int = 4) -> str:
    q_vec = embed(question)
    hits = vector_db.search(q_vec, top_k=k)
    hits = [h for h in hits if h.score > 0.72]     # فلترة ترفع الجودة كثيراً
    return "\n\n---\n\n".join(f"[{h.source}]\n{h.text}" for h in hits)


SYSTEM = (
    "أنت مساعد يجيب من المقاطع المرفقة فقط.\n"
    "- إن لم تجد الجواب، قل: «لا أعرف من المستندات الحالية».\n"
    "- اذكر المصدر بعد كل جملة بين قوسين.\n"
    "- لا تُخمّن أرقاماً أو تواريخ غير موجودة في السياق."
)

السطر الأخير هو الأهم عملياً. بلا تعليمات صريحة بالتوقف عند الجهل، سيخترع النموذج جواباً مقنعاً تماماً — وهذا أخطر من الخطأ الواضح.

حلقة التخطيط والتنفيذ

def run_agent(goal: str, max_steps: int = 8) -> str:
    messages = [
        {"role": "system", "content": SYSTEM_AGENT},
        {"role": "user", "content": goal},
    ]

    for step in range(max_steps):
        resp = llm.chat(messages, tools=TOOLS)

        if not resp.tool_calls:
            return resp.content                  # إجابة نهائية

        messages.append(resp.as_message())
        for call in resp.tool_calls:
            fn = REGISTRY[call.name]
            try:
                result = fn(**call.args)
            except Exception as e:
                result = {"error": str(e)}       # أرجِع الخطأ ليتعافى النموذج
            messages.append({
                "role": "tool",
                "tool_call_id": call.id,
                "content": json.dumps(result, ensure_ascii=False),
            })

    return "تجاوزت الحد الأقصى للخطوات — يحتاج الأمر مراجعة بشرية."

لاحظ max_steps: الوكيل بلا سقف يمكن أن يدور في حلقة لا نهائية ويكلّفك مالاً حقيقياً. السقف ليس ترفاً.

التقييم

الوكيل بلا تقييم مشروع بلا اختبارات. ابدأ بمجموعة صغيرة (20–50 حالة) وقيّم كل تغيير عليها:

  • دقة الأداة: هل استدعى الأداة الصحيحة؟
  • دقة الوسائط: هل مرّر القيم الصحيحة؟
  • الاكتمال: هل وصل للنتيجة المطلوبة؟
  • الالتزام: هل تجاوز الصلاحيات أو خلط المصادر؟

المقياس الأبسط والأكثر فائدة: نسبة الحالات التي احتاجت تدخلاً بشرياً. كلما انخفضت، تحسّن الوكيل.

التكلفة والخصوصية

القرارالأثر
عدد الخطواتتكلفة تتناسب طردياً — السياق يزيد في كل دورة
حجم مقاطع RAG3 مقاطع أفضل من 10 في الأغلب: سياق أقل = دقة أعلى
تلخيص السياق دورياًيخفض التكلفة 40–60% في الجلسات الطويلة
نموذج محلي للتصنيفيوفّر الاستدعاء الكبير للمهام المعقّدة فقط

للبيانات الحساسة: شغّل نموذجاً محلياً (Ollama) أو استخدم عقوداً مع ضمان عدم استخدام بياناتك في التدريب. القرار ليس تقنياً بحتاً — هو قرار سياسة بيانات.

قائمة بناء

  1. عرّف الهدف بجملة واحدة قابلة للقياس.
  2. اكتب 3 أدوات فقط في البداية — الأقل غالباً أفضل.
  3. اجعل كل أداة ترجع بيانات صغيرة ومنظّمة (لا نصوص ضخمة).
  4. أضف سقفاً للخطوات ومهلة زمنية وميزانية تكلفة.
  5. ابنِ مجموعة تقييم من 20 حالة حقيقية قبل أن تنشر.
  6. أضف نقطة تدخّل بشري لكل إجراء لا رجعة فيه (حذف، دفع، إرسال).
الخطوة التالية: اختر أداة داخلية تستخدمها يومياً (بحث في قاعدة البيانات، إرسال بريد…)، وغلّفها كأداة للنموذج. ابدأ بأداة واحدة فقط، واختبر عشرين سؤالاً حقيقياً عليها.
