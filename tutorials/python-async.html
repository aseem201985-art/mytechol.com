فهم Async/Await في بايثون من الصفر حتى الإنتاج

شرح عملي لكيفية عمل حلقة الأحداث (Event Loop) والـ Coroutines، مع أمثلة على بناء خدمة سريعة تجمع بين I/O المتزامن وغير المتزامن.

أأحمد
· 2025-02-18 · 14 دقيقة قراءة · متوسط
async

لو سألتني عن الفرق الوحيد الذي رفع أداء خدماتي أكثر من أي تحسين آخر، لقلت بلا تردد: التفكير في الـ I/O قبل التفكير في المعالج. معظم الوقت الذي «يضيع» في تطبيق ويب لا يُصرف في الحساب، بل في الانتظار: انتظار قاعدة البيانات، انتظار واجهة API خارجية، انتظار القرص.

لماذا Async أصلاً؟

تخيّل مطعماً فيه طاهٍ واحد. في النموذج المتزامن، الطاهي يستقبل طلباً، يضع الطعام على النار، ثم يقف ينظر إلى القدر حتى ينضج قبل أن يستقبل الطلب التالي. في النموذج غير المتزامن، يضع الطعام على النار ويقول «سأعود عندما ينضج»، ويستقبل طلباً آخر فوراً.

المهم: هناك طاهٍ واحد في الحالتين. Async لا يزيد عدد الأنوية، لكنه يمنع هدرها في الانتظار.

Async مفيد عندما تكون المهمة I/O-bound (شبكة، قرص، قاعدة بيانات). إذا كانت CPU-bound (معالجة صور، حسابات ثقيلة) فالحل هو العمليات المتوازية (multiprocessing) لا Async.

حلقة الأحداث (Event Loop)

حلقة الأحداث هي مُنظّم: تحتفظ بطابور من المهام. عندما تصل مهمة إلى نقطة انتظار (await)، تتركها الحلقة وتنتقل إلى مهمة أخرى جاهزة. عندما ينتهي الانتظار، تُعاد المهمة إلى الطابور لتُكمل من حيث توقفت.

  • Coroutine: دالة معرّفة بـ async def — لا تُنفَّذ عند استدعائها، بل تُرجع كائناً قابلاً للانتظار.
  • Task: Coroutine تم جدولتها لتعمل بالتوازي مع غيرها.
  • await: نقطة تسليم السيطرة للحلقة، لا «توقّف» للبرنامج.

أول دالة غير متزامنة

import asyncio, time

async def fetch_user(uid: int) -> dict:
    await asyncio.sleep(1)          # محاكاة طلب شبكة
    return {"id": uid, "name": f"user-{uid}"}

async def main():
    t0 = time.perf_counter()

    # خطأ شائع: كل await ينتظر الذي قبله
    for i in range(3):
        await fetch_user(i)

    print(f"تسلسلي: {time.perf_counter() - t0:.2f}s")   # ~3.00s

asyncio.run(main())

النتيجة قرابة ثلاث ثوانٍ: كل await ينتظر السابق. هذا هو الخطأ الأول الذي يرتكبه من ينتقل من Sync إلى Async — يكتب كوداً غير متزامن لكنه ينفّذه بشكل متسلسل.

التنفيذ المتوازي مع gather

async def main():
    t0 = time.perf_counter()

    # متوازٍ: الثلاثة يبدؤون في نفس اللحظة
    users = await asyncio.gather(
        fetch_user(1),
        fetch_user(2),
        fetch_user(3),
    )

    print(f"متوازٍ: {time.perf_counter() - t0:.2f}s")    # ~1.00s
    print(users)

asyncio.run(main())

ثانية واحدة بدل ثلاث. وبنفس النسبة، لو كان لديك 50 طلباً ستنتقل من خمسين ثانية إلى ثانية واحدة تقريباً.

معالجة الأخطاء داخل gather

السلوك الافتراضي: إذا فشل أحد المهام، تُلغى البقية وتُرفع أول استثناء. للتحكم الكامل استخدم return_exceptions=True:

results = await asyncio.gather(
    fetch_user(1),
    risky_operation(),
    fetch_user(3),
    return_exceptions=True,     # لا تُسقط الدفعة كلها بسبب فشل واحد
)

for r in results:
    if isinstance(r, Exception):
        print("فشل أحد المهام:", r)
    else:
        print("نجح:", r)

التعامل مع الكود المتزامن

هذه نقطة يفشل فيها كثيرون: كل استدعاء متزامن طويل داخل async def يجمّد حلقة الأحداث بالكامل — لأن الحلقة تعمل على خيط واحد.

import asyncio, time

def heavy_sync_call():
    time.sleep(2)               # يجمّد حلقة الأحداث بالكامل!
    return "done"

async def main():
    # ❌ سيوقف كل المهام الأخرى لثانيتين
    # heavy_sync_call()

    # ✅ نفّذها في خيط منفصل
    result = await asyncio.to_thread(heavy_sync_call)
    print(result)

للمكتبات التي لا تدعم Async إطلاقاً (مثل requests) استخدم asyncio.to_thread. وللمكتبات الحديثة، استخدم البديل غير المتزامن مباشرة (httpx بدل requests، وasyncpg بدل psycopg2).

استخدم TaskGroup في بايثون 3.11+

async def main():
    async with asyncio.TaskGroup() as tg:
        t1 = tg.create_task(fetch_user(1))
        t2 = tg.create_task(fetch_user(2))
    # هنا كل المهام انتهت، وأي استثناء يُرفع كـ ExceptionGroup
    print(t1.result(), t2.result())

دائماً ضع مهلة زمنية

async def fetch_with_timeout(uid: int):
    try:
        async with asyncio.timeout(3.0):
            return await fetch_user(uid)
    except TimeoutError:
        return None

إلى الإنتاج: قائمة تحقّق

  1. حدّد المهلات في كل استدعاء خارجي — بلا استثناء.
  2. حدّد التزامن بـ asyncio.Semaphore عند استدعاء خدمة خارجية.
  3. أعد المحاولة بانحدار أسّي مع jitter.
  4. راقب الحلقة: أي مهمة تزيد عن 100ms تظهر في السجلات كتحذير.
  5. اختبر تحت الحمل: Async يخفي المشاكل حتى يصل عدد الطلبات لألف.

حدّ التزامن العملي

sem = asyncio.Semaphore(10)     # 10 طلبات متزامنة كحد أقصى

async def limited_fetch(uid: int):
    async with sem:
        return await fetch_user(uid)

async def main():
    results = await asyncio.gather(*(limited_fetch(i) for i in range(100)))
    print(len(results))
الخطوة التالية (5 دقائق): افتح خدمتك الحالية وابحث عن await داخل حلقة for. إن وجدت واحداً، حوّله إلى gather وقس الفرق — سترى التحسّن فوراً.
