Git للمحترفين: إعادة كتابة التاريخ بأمان وبدون كوارث

rebase، cherry-pick، bisect، reflog، و autosquash — متى تستخدم كلاً منها وكيف تتراجع إذا حدث الأسوأ. مع سيناريوهات حقيقية وحلولها.

مفريق MyTechol
· 2025-11-18 · 15 دقيقة قراءة · متقدم
git

معظم المطورين يستخدمون 8 أوامر من أصل مئات، ثم يخافون من الباقي. النتيجة: تاريخ مستودع مليء بـ «fix» و«update» و«final-final»، ومراجعات كود تعذّب الفريق.

هذا الدرس لا يعلّمك أوامر، بل نموذجاً ذهنياً يجعل Git واضحاً.

الفهم الذي يغيّر كل شيء

Git ليس «مجلداً بسجل تغييرات». Git هو رسم بياني موجّه من الـ commits. كل commit هو لقطة كاملة، ويعرف آباءه. الفروع مجرد مؤشرات إلى عقدة في هذا الرسم — وهذا سبب أن إنشاء فرع فوري ومجاني.

{{
git log
git log --graph --oneline --all --decorate
# * 91ab3f2 (HEAD -> main, origin/main) feat: add rate limiting
# * 4d2c8e1 fix: handle empty payload
# *   a8f9321 Merge branch 'feature/search'
# |\\
# | * 2b7e1c9 feat: search index warmup
# | * 1a0d4b3 feat: search endpoint
# |/
# * 7f3c211 chore: bump deps  <-- القاعدة المشتركة
}}
ثلاث مناطق يجب التمييز بينها دائماً: Working Directory (ملفاتك)، Index/Staging (ما سيُضمَّن في الـ commit التالي)، وHEAD (آخر commit). 90% من الحيرة تنتهي حين تفصل بينها بوضوح.

Rebase بلا خوف

القاعدة الذهبية: rebase على فروعك الخاصة، ولا rebase على فرع مشترك دفع إليه غيرك.

{{
rebase
# اسحب آخر تغييرات main وأعد بناء فرعك فوقها
git fetch origin
git rebase origin/main

# أثناء التعارض:
git status                 # الملفات المتعارضة
# ... عدّل الملفات ...
git add <file>
git rebase --continue      # أو --skip أو --abort
}}

المقارنة العملية:

mergerebase
التاريخيحفظ الواقع كما حدثتاريخ خطّي نظيف
الاستخدامفرع مشترك / mainفرع شخصي قبل الدمج
الخطورةمنخفضةعالية على فرع عام

Interactive Rebase: نظّف قبل أن تطلب مراجعة

{{
rebase -i
git rebase -i HEAD~5

# pick   4d2c8e1 feat: add validation
# squash 9a1f2b3 fix typo              <- ادمجه في السابق
# reword 2c7b9a4 feat: add logging     <- عدّل الرسالة
# drop   1b8e3f7 wip                   <- احذفه نهائياً
# edit   a1c2d3e feat: partial         <- عدّل المحتوى
}}

حيلة تُوفّر وقتاً: اجعل Git يدمج إصلاحاتك تلقائياً في الـ commit الأصلي:

{{
autosquash
# أثناء العمل، أنشئ fixup بدلاً من commit عادي
git commit --fixup=<sha-of-original>

# لاحقاً، دمج تلقائي بلا فتح محرّر
GIT_SEQUENCE_EDITOR=: git rebase -i --autosquash origin/main
}}

bisect: العثور على الخطأ بين 500 commit

عندما يكسر شيء ما الموقع ولا تعرف أين، لا تقرأ الـ commits واحداً واحداً. استخدم البحث الثنائي — يجد الجاني في 9 خطوات من أصل 500 commit.

{{
bisect
git bisect start
git bisect bad                 # الحالة الحالية مكسورة
git bisect good v1.4.0         # هذه النسخة كانت سليمة

# Git يودّعك على commit وسطي: اختبره ثم:
git bisect good   # أو git bisect bad
# ... كرّر حتى: "<sha> is the first bad commit"

git bisect reset               # عُد إلى ما كنت عليه
}}

وللأتمتة الكاملة:

{{
bisect run
git bisect run npm test
# Git يشغّل الاختبارات على كل نقطة ويخبرك بالـ commit الأول الفاشل
}}

reflog: شبكة الأمان التي تُنقذك

كل عملية تُحرّك HEAD تُسجَّل في reflog لمدة 90 يوماً افتراضياً. حتى لو حذفت فرعاً أو أفسدت rebase، يمكنك العودة.

{{
reflog
git reflog
# 91ab3f2 HEAD@{{0}}: rebase (finish): returning to refs/heads/main
# 4d2c8e1 HEAD@{{1}}: rebase (start): checkout origin/main
# a8f9321 HEAD@{{2}}: commit: feat: add rate limiting

git reset --hard HEAD@{{2}}      # عُد بالضبط لما قبل الـ rebase
git branch rescue 4d2c8e1      # أو أنشئ فرعاً من commit مفقود
}}
قاعدة ذهبية: لا تُشغّل git reset --hard قبل أن تنظر في git reflog وتكتب الـ SHA الذي تريد العودة إليه. الـ reflog هو ما يفرّق بين «أخطأت» و«دمّرت يوم عملي».

قواعد الفريق التي تمنع الكوارث

  1. فعّل الحماية على main: لا دفع مباشر، مراجعة إلزامية.
  2. اربط الفروع بالمهام: feat/PROJ-142-rate-limit.
  3. رسائل واضحة: type(scope): subject — feat, fix, refactor, docs, chore.
  4. commit صغير ومتماسك: commit واحد = فكرة واحدة قابلة للتراجع عنها.
  5. فعّل Husky + lint-staged ليمنع الـ commit المكسور قبل أن يصل.
{{
git config
# اضبط سلوك السحب الافتراضي لتجنّب merge commits غير مقصودة
git config --global pull.rebase true
git config --global fetch.prune true
git config --global rerere.enabled true   # يتذكّر حلول التعارض
}}
الخطوة التالية: نفّذ git reflog الآن في مستودعك، وأعد commitاً حذفته سابقاً في فرع تجريبي. تمرين 30 ثانية يمنحك ثقة تدوم.
