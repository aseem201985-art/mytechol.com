أمان تطبيقات الويب: الثغرات العشر التي تُخترق بها المواقع فعلاً

ليست قائمة نظرية — بل الثغرات المتكررة في تقارير الاختبار الحقيقية: SQLi، XSS، IDOR، رفع الملفات، والأسرار المكشوفة. مع الكود الصحيح لكل واحدة.

SEC

الاختراقات الحقيقية نادراً ما تكون عمليات معقّدة. في معظم تقارير الحوادث، نقطة الدخول بسيطة: استعلام واحد غير مُعامل، أو معرّف لم يُتحقَّق من ملكيته، أو مفتاح API في مستودع عام.

لماذا تُخترق المواقع؟

لأن الأمان يُعتبر «مرحلة لاحقة». لكن التكلفة الحقيقية ليست إضافة طبقة أمان — بل كتابة الكود بطريقة صحيحة من البداية، وهي غالباً لا تكلّف أسطراً إضافية.

1. حقن SQL: لا يزال حياً

رغم كل التحذيرات، لا يزال في المرتبة الأولى في تقارير كثيرة.

{{
sqli.py
# ✗ كارثة: النص يدخل مباشرة إلى الاستعلام
cur.execute(f"SELECT * FROM users WHERE email = '{{email}}'")
# المدخل: ' OR '1'='1' --   => إرجاع كل المستخدمين

# ✓ معاملات (parameterized): القاعدة تتعامل مع القيمة كبيانات لا ككود
cur.execute("SELECT id, name FROM users WHERE email = %s", (email,))
row = cur.fetchone()
}}

الحالات التي يخطئ فيها الناس:

  • أسماء الجداول والأعمدة لا يمكن تعقيدها كمعاملات — استخدم قائمة بيضاء صريحة.
  • ORDER BY وLIMIT تحتاج تحققاً يدوياً.
  • ORMs ليست مناعة تلقائية: raw() وextra() تعيد الثغرة.
{{
sqli-safe.py
SORTABLE = {{"created_at", "name", "score"}}   # قائمة بيضاء

def list_users(sort: str, limit: int = 20):
    col = sort if sort in SORTABLE else "created_at"
    limit = max(1, min(limit, 100))          # حدّ صريح يمنع الإفراغ
    cur.execute(f"SELECT id, name FROM users ORDER BY {{col}} LIMIT %s", (limit,))
}}

2. XSS: تصاعد في ثلاث طبقات دفاع

{{
xss.py
# طبقة 1: الترميز عند العرض — الدفاع الأساسي
from markupsafe import escape
template = f"<h2>مرحباً {{escape(user_name)}}</h2>"

# طبقة 2: Content Security Policy — يمنع تنفيذ سكربتات غير مصرّح بها
# Header: Content-Security-Policy:
#   default-src 'self'; script-src 'self'; object-src 'none';

# طبقة 3: كوكيز HttpOnly تمنع سرقة الجلسة عبر JS
response.set_cookie("sid", token,
    httponly=True, secure=True, samesite="Lax", max_age=86400)
}}
لا تستخدم innerHTML مع مدخلات مستخدم أبداً. استخدم textContent، وإن احتجت HTML فاستخدم مُطهّراً جيداً (DOMPurify) وليس تعبيراً نمطياً.
{{
xss.js
// ✗
el.innerHTML = `<span>${{userInput}}</span>`;

// ✓
el.textContent = userInput;

// ✓ عند الحاجة لـ HTML فعلاً
import DOMPurify from "dompurify";
el.innerHTML = DOMPurify.sanitize(userHtml, {{ ALLOWED_TAGS: ["b", "i", "a"] }});
}}

3. IDOR: الثغرة المنطقية الأشهر

لا علاقة لها بـ SQL أو XSS. ببساطة: المستخدم يغيّر رقماً في الرابط ويصل لبيانات غيره.

{{
idor.py
# ✗ التحقق من تسجيل الدخول فقط
@app.get("/api/orders/{{order_id}}")
def get_order(order_id: int, user=Depends(current_user)):
    return db.orders.find_one({{"_id": order_id}})   # أي مستخدم يرى أي طلب!

# ✓ التحقق من الملكية في كل استعلام — ليس فلترة لاحقة
@app.get("/api/orders/{{order_id}}")
def get_order(order_id: int, user=Depends(current_user)):
    order = db.orders.find_one({{"_id": order_id, "user_id": user.id}})
    if not order:
        raise HTTPException(404)     # 404 لا 403 — لا تؤكد الوجود
    return order
}}
مبدأ مهم: أعد 404 لا 403 عند محاولة الوصول لمورد لا تملكه. الـ 403 يؤكد وجود المورد — وهذه معلومة يستغلها المهاجم.

4. المصادقة: تفاصيل تُهمَل

  1. كلمات المرور: استخدم argon2id أو bcrypt (cost ≥ 12). لا MD5/SHA أبداً.
  2. حدّ المحاولات: 5 محاولات/دقيقة/حساب + تأخير متزايد.
  3. رسائل خطأ موحّدة: «البريد أو كلمة المرور غير صحيحة» — لا تكشف أيّهما.
  4. الجلسات: جدّد المعرّف عند تسجيل الدخول (يمنع Session Fixation).
  5. 2FA: أضفها للحسابات الإدارية كحدّ أدنى.
{{
auth.py
from argon2 import PasswordHasher
from argon2.exceptions import VerifyMismatchError

ph = PasswordHasher(time_cost=3, memory_cost=65536, parallelism=4)

def hash_password(pw: str) -> str:
    return ph.hash(pw)            # يحتوي الملح تلقائياً

def verify(pw: str, stored: str) -> bool:
    try:
        ph.verify(stored, pw)
        return True
    except VerifyMismatchError:
        return False
}}

5. رفع الملفات: مساحة هجوم كاملة

  • لا تثق بالامتداد: تحقّق من النوع الفعلي (magic bytes).
  • لا تخزّن في جذر الموقع: استخدم مخزناً خارجياً أو مجلداً غير قابل للتنفيذ.
  • حدّد الحجم قبل القراءة، لا بعدها (منع استنزاف القرص).
  • أعد تسمية الملف بمعرّف عشوائي — لا تحتفظ بالاسم الأصلي في المسار.
{{
upload.py
ALLOWED = {{"image/jpeg", "image/png", "image/webp"}}
MAX_BYTES = 5 * 1024 * 1024

async def save_upload(file: UploadFile):
    head = await file.read(512)                    # اقرأ البداية فقط للفحص
    mime = magic.from_buffer(head, mime=True)
    if mime not in ALLOWED:
        raise HTTPException(415, "نوع الملف غير مدعوم")

    name = f"{{uuid4().hex}}.{{mime.split('/')[1]}}"   # اسم مولَّد، لا اسم المستخدم
    dest = UPLOAD_DIR / name
    size = 0
    with dest.open("wb") as f:
        while chunk := await file.read(65536):
            size += len(chunk)
            if size > MAX_BYTES:
                f.close(); dest.unlink(missing_ok=True)
                raise HTTPException(413, "الملف كبير جداً")
            f.write(chunk)
    return name
}}

6. الأسرار المكشوفة: صامتة ومدمّرة

مفاتيح API في مستودع عام = مخترق في دقائق. حتى في مستودع خاص، فهي تبقى في تاريخ Git للأبد.

{{
secrets.sh
# افحص قبل كل دفع
git secrets --scan
# أو
gitleaks detect --source . --verbose

# لا تضع أبداً .env في Git
echo ".env*" >> .gitignore

# للأسرار في CI
gh secret set DATABASE_URL
}}
إذا كشفت سرّاً عن طريق الخطأ: أبطِله فوراً. حذف الـ commit غير كافٍ — يبقى في reflog وفي مرايا الأطراف الثالثة.

#الثغرةالعلاج في سطر

10تسريب معلوماتلا تُظهر stack traces في الإنتاج

قائمة تحقّق قبل النشر

  1. كل استعلام SQL معامَلي (parameterized).
  2. ترميز كل مخرجات المستخدم + CSP مفعّل.
  3. تحقّق من الملكية في كل مسار يصل لمورد.
  4. Argon2/bcrypt + حدّ محاولات + رسائل موحّدة.
  5. رفع ملفات: نوع فعلي + حجم + اسم مولَّد.
  6. لا أسرار في Git — فحص تلقائي في CI.
  7. HTTPS إلزامي + HSTS + كوكيز Secure; HttpOnly.
  8. نسخ احتياطي مشفّر ومُختبَر استعادته.
الخطوة التالية: ابحث في مشروعك عن f"SELECT وinnerHTML. أي نتيجة هي نقطة بدء فورية — إصلاحها يستغرق 10 دقائق، ويمنع أخطر ثغرتين.
