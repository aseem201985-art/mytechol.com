تصميم APIs RESTful بشكل احترافي

أسماء الموارد، رموز الحالة، الإصدار، التوثيق، والأخطاء. كيف تبني API يُحبّه المطورون الذين يستخدمونه؟

مفريق MyTechol
· 2025-11-10 · 12 دقيقة قراءة · متوسط
API

API الجيد هو الذي يُفهم من أول استخدام. المطورون لا يقرأون التوثيق الطويل؛ يقرأون الاستجابة الأولى. هذا دليل عملي لتصميم APIs RESTful واضحة.

الموارد والأسماء

استخدم أسماء موارد لا أفعال:

GET    /users
GET    /users/42
POST   /users
PATCH  /users/42
DELETE /users/42

رموز الحالة

  • 200 OK، 201 Created، 204 No Content
  • 400 Bad Request، 401 Unauthorized، 403 Forbidden
  • 404 Not Found، 409 Conflict، 422 Unprocessable
  • 500 Internal Server Error

تنسيق الأخطاء

{
  "error": {
    "code": "INVALID_EMAIL",
    "message": "صيغة البريد غير صحيحة",
    "field": "email"
  }
}

الإصدار

ضع الإصدار في المسار: /v1/users. لا تُغيّر سلوك API الحي دون تغيير الإصدار.
